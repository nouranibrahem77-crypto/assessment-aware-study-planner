# P1 Search and CSP design

## Scope and status

This document records the P1 design rationale and summarizes the current
implementation. Search algorithms are under `src/study_planner/search/`, CSP
solvers are under `src/study_planner/csp/`, NN training and inference are under
`src/study_planner/nn/`, and their orchestration is under
`src/study_planner/integration/`. The requirements below are those recorded
from the project brief. Descriptions marked as proposed or unresolved distinguish
design intent and pending application inputs from implemented behavior. Demo
settings are synthetic/test configuration, not production policy.

## Official P1 requirements

- Plan one course with three assignments by assigning a number of study
  sessions to each assignment and determining their weeks.
- Search starts with zero sessions. Each action adds exactly one session to one
  assignment. Find the smallest plan whose predicted marks meet the target.
- The integrated planner uses Uniform Cost Search (UCS) and Greedy Best-First
  Search. A* is implemented for the required Experiment 1 algorithm comparison;
  it is not added to planner orchestration.
- Search proposes a plan, the NN predicts marks, and CSP checks whether the
  sessions can be scheduled. If CSP rejects a candidate, discard it and
  continue Search.
- CSP requires every session before its assignment deadline, at most one
  session in each weekly time slot, and ordered sessions for each assignment.
- If no solution exists, report that the target is unreachable at available
  capacity and show the best achievable predicted marks.
- Minimum project scope also includes Backtracking, Forward Checking, and
  AC-3.
- Model A Strict predicts from assessment metadata and recent online-learning
  clicks; its feature schema excludes previous assessment marks. Model B
  Previous-Marks Proxy adds prior-score lags and availability indicators using
  submission timing as a proxy. OULAD has no grade-release timestamps, so Model
  B does not establish that a prior mark was visible at prediction time.
- Session click increments, slot capacity, and target mark are generated by
  documented rules. Session length in clicks is not an observed fact.
- Test monotonicity over increasing session allocations and report violations.
- Interpret the effort-mark relationship as observational/simulated, not
  causal.

## Proposed Search formulation

**State.** The application represents an allocation as a canonical immutable
tuple of non-negative counts for each assignment and each of its four
assessment-relative windows, together with the problem identity needed to
interpret it. Eligible windows derive from the supplied slot catalog and
deadline policy. This state records allocation counts; CSP later chooses the
concrete slots. State equality is exact equality of the canonical allocation,
so equivalent paths to the same allocation are duplicates.

**Initial state.** Every count is zero. Reject malformed problem inputs (for
example, missing assignment definitions or invalid deadlines) before Search.

**Actions and transition.** The application allocation state stores four
assessment-relative window counts per assignment. An action selects an
assignment and an eligible relative window, then adds one session there. The
configured slot catalog maps eligible slots to those windows; CSP later assigns
each session to a concrete slot. Session-to-Clicks Mapping deterministically
adds the configured synthetic increment to a copied candidate feature row,
changing only the selected click feature. It does not change source rows or
persisted datasets. The mapping supports documented low, central, and high
scenarios of 22, 62, and 121 clicks per hypothetical session; these are
training-anchored simulation values, not measured session lengths. Search
respects configured per-assignment allocation bounds, while CSP enforces
weekly slot capacity and deadline eligibility. Stable action ordering makes
ties reproducible.

**Goal test.** Generic Search uses the integration controller as its goal
predicate. For an allocation, the controller obtains provisional NN
predictions, enumerates CSP schedules, verifies each complete schedule, and
obtains schedule-specific final NN predictions. An allocation is accepted as a
goal only when a verified schedule has final predictions meeting all three
explicit assignment targets. A provisional prediction alone does not establish
a goal or an achievable mark. Course-level aggregate targets are not supported
by the current application input contract.

**Path cost.** Unit cost per added session, so `g(state)` is exactly the total
number of sessions in the allocation. All action costs are finite, positive,
and non-negative. Thus UCS returns a minimum-session Search goal when the
reachable state space is finite. Search continues past CSP-infeasible goals;
the first CSP-feasible goal removed from the UCS frontier is therefore the
smallest feasible plan, provided every allocation has a deterministic score
and CSP result and no candidate is incorrectly skipped.

**Boundaries and duplicates.** The validated application inputs provide each
assignment's eligible slot IDs, deadline policy, slot catalog, weekly capacity,
and allocation bounds. The allocation space derives available relative windows
from those eligible slots; CSP uses the configured domains and constraints to
place sessions. These values are caller-supplied and current demo values are
synthetic. Session mapping checks each modified click feature against
training-derived marginal minimum and maximum values; its p99 threshold is a
warning, and joint support is currently unassessed. The configured support
policy can report or reject out-of-range mappings. Finite allocation bounds
make the Search space finite. UCS stores the least known `g` for each canonical
state; with unit costs a state's first best path has minimum depth. Greedy
records discovered/expanded states to avoid repeated work. Rejected CSP
allocations are remembered so an identical candidate is not sent to CSP
repeatedly. Distinct allocation states must not be merged merely because their
predicted marks match.

**Termination and impossible cases.** For each allocation selected by UCS or
Greedy, the integration controller obtains provisional predictions, enumerates
CSP schedules, verifies each complete schedule, and obtains final
schedule-specific predictions. It accepts the first verified schedule whose
final predictions meet all three assignment targets. Rejected schedules and
target-missing predictions do not end schedule enumeration; if the allocation
has no qualifying schedule, Search continues in its priority order. The result
distinguishes an exhausted Search from invalid input, unsupported predictions,
operational errors, and configured resource limits; a limit hit is not proof
of unreachability. Best-achievable marks are based on evaluated final
predictions, not provisional predictions.

## UCS and Greedy Best-First Search

**UCS** prioritizes `g`, the number of sessions added. Because every action
costs one, all costs are non-negative and path cost equals plan size. UCS
therefore finds the least-session goal among the states it searches. With CSP
rejection integrated as above, it finds the smallest CSP-feasible goal, subject
to finite bounds and correct goal evaluation. Use a monotonic queue insertion
counter to break equal-cost ties deterministically, ignore stale queue entries,
and continue after a rejected candidate.

**Expansion-order distinction.** Standard UCS expands the lowest cumulative
path cost first. With unit session costs, this means candidates are examined in
non-decreasing session count. Standard Greedy Best-First Search instead
prioritizes the heuristic `h(state)` alone. It can expand a larger allocation
before a smaller one when that allocation has a lower predicted-score gap.
This is the intended algorithmic difference; do not impose UCS cost layers on
Greedy or describe Greedy as minimizing sessions. Both algorithms use the
same allocation state, provisional/final evaluator, NN and CSP interfaces,
duplicate policy, and acceptance/termination rules. Only their frontier
priority differs.

**Greedy heuristic.** Let `p_i(s)` be the predicted mark for assignment `i`
under state `s`, and `t_i` its target. A defensible gap measure, when targets
and marks share a scale, is
`h(s) = sum_i max(0, t_i - p_i(s))`. Lower gap states are expanded first;
the zero-gap condition matches the per-assignment target goal. This gap is an
example caller-supplied heuristic, not a fixed heuristic in the Search
implementation or a supported course-level target rule. It is a ranking
heuristic, not a lower bound on sessions: it has mark units, does not estimate
how many sessions close the gap, and gives no distance calibration. The
integration API accepts a deterministic heuristic callback. No weights,
normalization, effort-to-score slope, or tie parameters are built into it.
Greedy ignores sessions already spent (`g`) and can choose a longer solution
or fail to find the minimum-session plan; it is not optimal. Tie-break
deterministically (for example, insertion order). If an allocation has no
defined prediction, the planner must surface that condition rather than
fabricate a heuristic value.

**Monotonicity audit.** The reporter compares observations in the same
learner, assessment, model, and mapping context when one allocation adds a
session while other allocation counts remain fixed. Its default tolerance is
zero. It records negative prediction changes as violations and reports the
compared observations, changed feature/window, prediction delta, and violation
rate. Do not sort, clip, repair, or suppress violating predictions. This audits
simulated model response, not a causal effect or a guarantee about real
learners. The current unconstrained MLP does not guarantee monotonicity.

Both algorithms can have exponential time and memory in the number of
assignment/week allocation dimensions and their bounds. UCS can additionally
expand many low-session states before a goal; Greedy's guidance depends on
prediction quality and can be misled. Exact bounds depend on supplied weeks
and capacities.

## NN and CSP interfaces

**Session mapping and NN boundary.** The `SessionNNAdapter` keeps model mode,
feature schema, artifact digest, mapping context, and prediction provenance
explicit. Both NN modes use separate schemas and artifacts:

- **Model A Strict** excludes all previous-assessment-score features. It uses
  strict FFF assessment metadata and recent click features.
- **Model B Previous-Marks Proxy** includes prior-score lags and availability
  indicators. A prior score is included only under the documented
  submission-based rule; OULAD has no release timestamp, so availability to the
  student at prediction time is unverified. Treat this as a proxy sensitivity
  mode, not leakage-cleared historical input.

The mapping component copies the observed feature context and changes only the
configured `click_<group>_week_<1..4>` features. It preserves the original
source row and records the synthetic scenario, changed feature, support
diagnostics, and candidate identity. Inference validates the selected model's
own schema; the strict and proxy feature schemas are not merged.

The click increment is generated by a documented rule, not learned as a
causal effect. Even if candidate rows remain within support, the MLP's
predictions on synthetic inputs describe model response to an assumed feature
perturbation; they do not establish that a study session creates those clicks
or changes a real mark. Report monotonicity violations instead of altering
outputs. No monotonic guarantee is assumed.

**CSP boundary.** Input is a candidate allocation, assignment-specific slot
domains, the configured weekly capacity, deadline eligibility, and an explicit
same-assignment ordering policy. Output is a stream of distinct schedules plus
a verification result for each schedule and a terminal exhausted or incomplete
status. Backtracking (BT),
Forward Checking (BT+FC), and Forward Checking with AC-3 (BT+FC+AC-3) are
separately selectable. BT performs deterministic recursive backtracking;
Forward Checking removes values that fail constraints with one unassigned
variable and restores pruned domains on backtracking. AC-3 revises directed
arcs for explicit binary constraints and is combined with the solver's
backtracking and forward-checking work; it does not establish arc consistency
for n-ary constraints. The solvers expose counters for visited nodes,
assignments, backtracks, constraint checks, and applicable pruning or
compatibility checks.

In the integrated planner, each Search allocation is evaluated by provisional
prediction, CSP schedule enumeration, whole-plan verification, and final
schedule-specific prediction. A verification-rejected schedule is skipped; a
target-missing final prediction does not end enumeration of other schedules.
If no schedule for the allocation yields a target-reaching verified plan,
Search continues according to UCS or Greedy priority. The result distinguishes
target unreachable after exhaustive Search, no feasible schedule, unsupported
plans, resource-limited incomplete Search, and operational errors. A* is
available for standalone Search comparison, but integrated orchestration
selects UCS or Greedy.

## Evaluation and tests

For each Search algorithm, record nodes expanded, nodes generated (successors
produced before duplicate filtering), solution cost in sessions, and runtime.
Run at least five fixed seeds for the planner experiments and
report mean and standard deviation for applicable metrics. Search is
deterministic under fixed inputs and tie-breaking; seeds should identify
experimental variation, not introduce uncontrolled algorithm randomness.
Compare UCS and Greedy on the same problem instances for solution success,
session cost, nodes expanded, nodes generated, runtime, success/failure, final
predicted marks, and CSP feasibility. Report actual solution cost for either
algorithm; Greedy may return a higher-cost solution. Experiment 1 also compares
A* with a consistent heuristic; this does not change the integrated planner's
UCS/Greedy selection.

Required tests should include:

- normal feasible plans and each of the three assignments;
- edge cases: zero sessions already meets target, deadline boundary, capacity
  boundary, repeated/equivalent allocation paths, deterministic ties;
- a small known-answer problem where minimum session count is calculable;
- a Greedy example that finds a valid but non-minimal plan;
- impossible target/capacity and complete no-solution behavior, including best
  achievable predicted marks;
- CSP rejection followed by Search continuing to a feasible candidate;
- CSP checks for deadline, unique weekly slots, and ordered same-assignment
  sessions;
- invalid inputs and predictions that cannot be evaluated.

## Architecture fit

Keep generic algorithms and allocation/search results in the existing
`src/study_planner/search/` package. Keep scheduling constraints and the three
CSP methods in `src/study_planner/csp/`. Use a narrow orchestration layer under
`integration/` to call Search, the NN adapter, and CSP and to resume Search
after rejection. Preserve the existing NN inference interface and artifacts.
The package layout already contains `search`, `csp`, and `integration` seams;
this design adds responsibilities without moving existing ML code.

## Unresolved assumptions and decisions

The implementation currently requires one explicit target per assignment;
course-level target aggregation is not implemented. The remaining unresolved
production inputs and rubric decisions are:
- production assignment identities, eligible-slot inputs, and approved
  deadline-policy values; the planner validates supplied values rather than
  deriving production eligibility from local clock fields;
- authoritative slot catalog, time windows, capacity, allocation bounds, and
  same-assignment ordering policy. The demo uses synthetic settings; production
  values and policy approvals remain external inputs;
- the selected low/central/high click scenario and assignment-relative window
  mapping for a production application. The available click increments are
  simulation inputs, not measured study-session durations;
- the production support-policy reference and disposition. Current support
  checks are marginal; joint support is unassessed;
- a defensible grade-release availability cutoff for Model B prior marks.
  Model A Strict avoids prior-mark inputs; Model B remains an unverified
  submission-based proxy;
- production policy for interpreting unsupported predictions and
  best-achievable marks when not every allocation has a supported score;
- the approved production experiment scenarios and application configuration.
  The synthetic/test experiment protocol, fixed seeds, and metric definitions
  are documented separately in `docs/experiment_protocol.md`.

Do not treat synthetic click increments, capacities, or targets as production
rules, or select missing production values, support thresholds, or heuristic
parameters without the relevant approval. The mapping is a declared simulation
input, not a discovered causal session-to-mark relationship.
