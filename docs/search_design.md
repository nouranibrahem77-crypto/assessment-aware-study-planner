# P1 Search and CSP design

## Scope and status

This is a design-only document. No Search, CSP, or ML code is implemented or
changed here. The first section records the official P1 requirements provided
with the project brief. The following design choices make those requirements
implementable while marking inputs the brief/repository do not settle.

## Official P1 requirements

- Plan one course with three assignments by assigning a number of study
  sessions to each assignment and determining their weeks.
- Search starts with zero sessions. Each action adds exactly one session to one
  assignment. Find the smallest plan whose predicted marks meet the target.
- Implement Uniform Cost Search (UCS) and Greedy Best-First Search. A* is an
  optional extension only.
- Search proposes a plan, the NN predicts marks, and CSP checks whether the
  sessions can be scheduled. If CSP rejects a candidate, discard it and
  continue Search.
- CSP requires every session before its assignment deadline, at most one
  session in each weekly time slot, and ordered sessions for each assignment.
- If no solution exists, report that the target is unreachable at available
  capacity and show the best achievable predicted marks.
- Minimum project scope also includes Backtracking, Forward Checking, and
  AC-3.
- The NN predicts marks from previous marks and recent online-learning clicks.
- Session click increments, slot capacity, and target mark are generated by
  documented rules. Session length in clicks is not an observed fact.
- Test monotonicity over increasing session allocations and report violations.
- Interpret the effort-mark relationship as observational/simulated, not
  causal.

## Proposed Search formulation

**State.** Represent the partial allocation by a canonical immutable tuple of
non-negative session counts indexed by assignment and week, plus any fixed
problem identity needed to interpret the tuple. The three assignments and
eligible weeks come from the validated planning input. Counts make Search
states independent of which exact weekly time slot CSP later chooses. If the
specification intends Search to choose weeks differently, the count tuple
captures that; the CSP assigns actual slots. State equality is exact equality
of this canonical allocation, so equivalent paths to the same allocation are
duplicates.

**Initial state.** Every count is zero. Reject malformed problem inputs (for
example, missing assignment definitions or invalid deadlines) before Search.

**Actions and transition.** An action selects one assignment and one eligible
week, then increments exactly that allocation by one session. A separate
Session-to-Clicks Mapping component deterministically converts that added
session into a configured synthetic click increment. Its configuration names
the activity group, one of the strict feature's four deadline-relative weeks,
and the click-length rule; this document deliberately defines no numeric
length. Reject a session at or after its assessment cutoff. The component
copies the candidate feature row and changes only the selected click feature;
historical source rows and persisted datasets remain immutable. The transition
cannot exceed the generated capacity bound. Stable action ordering makes ties
reproducible.

**Goal test.** Predict marks for the candidate allocation and check the
specified target criterion. If marks are required per assignment, compare each
prediction with its assignment target; if there is one course-level target,
apply the official course-level rule. The target aggregation rule must be
confirmed (see unresolved decisions). A Search goal is not accepted as a
solution until CSP finds a feasible schedule.

**Path cost.** Unit cost per added session, so `g(state)` is exactly the total
number of sessions in the allocation. All action costs are finite, positive,
and non-negative. Thus UCS returns a minimum-session Search goal when the
reachable state space is finite. Search continues past CSP-infeasible goals;
the first CSP-feasible goal removed from the UCS frontier is therefore the
smallest feasible plan, provided every allocation has a deterministic score
and CSP result and no candidate is incorrectly skipped.

**Boundaries and duplicates.** Weeks are limited to those before each
assignment's deadline and within the supplied planning horizon. A documented
rule generates slot capacity; no numeric capacity is assumed here. A support
policy must be derived from training data without test access and specify how
to detect candidate click vectors outside observed support (including
per-feature ranges and, where feasible, multivariate support). Out-of-support
states must be flagged and excluded from claims of validated prediction;
whether they are pruned or scored only as exploratory scenarios is unresolved.
Finite capacity makes the allocation space finite.
UCS stores the least known `g` for each canonical state; with unit costs a
state's first best path has minimum depth. Greedy records discovered/expanded
states to avoid repeated work. Rejected CSP allocations are remembered so an
identical candidate is not sent to CSP repeatedly. Distinct allocation states
must not be merged merely because their predicted marks match.

**Termination and impossible cases.** Pop candidates in the algorithm's
priority order, evaluate the NN goal condition, then call CSP for goal
candidates. On CSP rejection, record the rejection and resume frontier search.
Terminate successfully at the first CSP-feasible goal under that ordering.
When the finite frontier is exhausted, return no solution, state that the
target is unreachable at available capacity, and report the best achievable
predicted marks among candidates evaluated under the defined scoring rule.
Distinguish this from invalid input or a configured resource limit; a limit
hit is not proof of unreachability. A zero-capacity or empty feasible-week
problem is a valid finite problem and may be impossible unless the zero-session
state meets the target.

## UCS and Greedy Best-First Search

**UCS** prioritizes `g`, the number of sessions added. Because every action
costs one, all costs are non-negative and path cost equals plan size. UCS
therefore finds the least-session goal among the states it searches. With CSP
rejection integrated as above, it finds the smallest CSP-feasible goal, subject
to finite bounds and correct goal evaluation. Use a monotonic queue insertion
counter to break equal-cost ties deterministically, ignore stale queue entries,
and continue after a rejected candidate.

**Expansion-order distinction.** Standard UCS expands the lowest cumulative
path cost first. With unit session costs, this means candidates are examined in
non-decreasing session count. Standard Greedy Best-First Search instead
prioritizes the heuristic `h(state)` alone. It can expand a larger allocation
before a smaller one when that allocation has a lower predicted-score gap.
This is the intended algorithmic difference; do not impose UCS cost layers on
Greedy or describe Greedy as minimizing sessions. Both algorithms use the
same allocation state, provisional/final evaluator, NN and CSP interfaces,
duplicate policy, and acceptance/termination rules. Only their frontier
priority differs.

**Greedy heuristic.** Let `p_i(s)` be the predicted mark for assignment `i`
under state `s`, and `t_i` its target. A defensible gap measure, when targets
and marks share a scale, is
`h(s) = sum_i max(0, t_i - p_i(s))`. Lower gap states are expanded first;
the zero-gap condition matches the per-assignment target goal. For a single
course-level target, define the corresponding gap from that official target
instead. This is a ranking heuristic, not a lower bound on sessions: it has
mark units, does not estimate how many sessions close the gap, and gives no
distance calibration. It requires a valid prediction for each candidate. No
weights, normalization, effort-to-score slope, or tie parameters are assumed.
Greedy ignores sessions already spent (`g`) and can choose a longer solution
or fail to find the minimum-session plan; it is not optimal. Tie-break
deterministically (for example, insertion order). If an allocation has no
defined prediction, the planner must surface that condition rather than
fabricate a heuristic value.

**Monotonicity audit.** Compare predicted marks for comparable states as
session allocations increase, using the same learner/assessment context and
mapping configuration. Define the tested order (for example, adding one
session while holding other assignments fixed) and a tolerance before
evaluation. Record every decrease as a violation with the allocation pair,
changed activity group/week, and prediction delta; report violation counts and
rates by assignment and configuration. Do not sort, clip, repair, or suppress
violating predictions. This audits simulated model response, not a causal
effect or a guarantee about real learners. The current unconstrained MLP does
not guarantee monotonicity.

Both algorithms can have exponential time and memory in the number of
assignment/week allocation dimensions and their bounds. UCS can additionally
expand many low-session states before a goal; Greedy's guidance depends on
prediction quality and can be misled. Exact bounds depend on supplied weeks
and capacities.

## NN and CSP interfaces

**Session mapping and NN boundary.** `RegressionPredictor.predict(features)`
accepts rows matching the saved strict FFF schema and returns clipped
predictions. The mapping component takes an immutable observed strict feature
row plus the proposed assignment/week action and configuration, and returns a
synthetic candidate row. It may alter only an appropriate
`click_<group>_week_<1..4>` field before that assessment's deadline. It must
preserve schema, identifiers as audit context (never model inputs), labels,
and the original observed feature values; only a copy is sent to inference.
The synthetic increment, configuration/version, support status, and affected
feature must be auditable. The existing NN architecture, strict feature
schema, and original artifacts remain unchanged.

The official previous-mark input requirement conflicts with the current strict
model contract: strict training/inference explicitly excludes all previous
assessment-score features. The optional proxy feature mode contains prior
scores but the repository documents that OULAD has no score-release timestamp;
submission before a later assessment cutoff does not prove the prior mark was
available then. Do not use proxy scores as if leakage-free. Adding prior marks
requires an availability cutoff and a separate leakage audit before any
schema/model changes or retraining. This design does not authorize those
changes.

The click increment is generated by a documented rule, not learned as a
causal effect. Even if candidate rows remain within support, the MLP's
predictions on synthetic inputs describe model response to an assumed feature
perturbation; they do not establish that a study session creates those clicks
or changes a real mark. Report monotonicity violations instead of altering
outputs. No monotonic guarantee is assumed.

**CSP boundary.** Input is a candidate allocation (assignment, week, session
counts), assignment deadlines, the available weekly time-slot domains, and the
fixed ordering convention. Output is either a feasible assignment of every
session to a concrete slot, or infeasible; an optional diagnostic may explain
the conflict. Enforce: slots precede that assignment's deadline; no slot hosts
more than one session; and sessions for one assignment respect the specified
order. The CSP solver comprises Backtracking, Forward Checking, and AC-3 as
required. Search calls CSP only for mark-goal candidates. On infeasibility it
discards that candidate, records it, and resumes the same frontier; the next
candidate is selected by UCS or Greedy ordering. Search reports success only
after a feasible CSP schedule is returned.

## Evaluation and tests

For each algorithm, record nodes expanded, nodes generated (define consistently
as successors considered, including duplicates), solution cost in sessions,
and runtime. Run at least five independent runs/seeds for experiments and
report mean and standard deviation for applicable metrics. Search is
deterministic under fixed inputs and tie-breaking; seeds should identify
experimental variation, not introduce uncontrolled algorithm randomness.
Compare UCS and Greedy on the same problem instances for solution success,
session cost, nodes expanded, nodes generated, runtime, success/failure, final
predicted marks, and CSP feasibility. Report actual solution cost for either
algorithm; Greedy may return a higher-cost solution. A* is not part of the
required implementation.

Required tests should include:

- normal feasible plans and each of the three assignments;
- edge cases: zero sessions already meets target, deadline boundary, capacity
  boundary, repeated/equivalent allocation paths, deterministic ties;
- a small known-answer problem where minimum session count is calculable;
- a Greedy example that finds a valid but non-minimal plan;
- impossible target/capacity and complete no-solution behavior, including best
  achievable predicted marks;
- CSP rejection followed by Search continuing to a feasible candidate;
- CSP checks for deadline, unique weekly slots, and ordered same-assignment
  sessions;
- invalid inputs and predictions that cannot be evaluated.

## Architecture fit

Keep generic algorithms and allocation/search results in the existing
`src/study_planner/search/` package. Keep scheduling constraints and the three
CSP methods in `src/study_planner/csp/`. Use a narrow orchestration layer under
`integration/` to call Search, the NN adapter, and CSP and to resume Search
after rejection. Preserve the existing NN inference interface and artifacts.
The package layout already contains `search`, `csp`, and `integration` seams;
this design adds responsibilities without moving existing ML code.

## Unresolved assumptions and decisions

The official requirements above do not specify:

- whether targets are per assignment or a course-level aggregate, and the
  exact aggregation/threshold rule;
- the assignment identifiers, weeks in horizon, week/deadline boundary
  convention, and how missing deadlines are handled;
- available weekly slots, capacity data/source, and whether capacity is global
  or assignment-specific;
- what “sessions ordered” means (strictly earlier distinct weeks, chronological
  session indices, or another precedence relation);
- the generated click-length, assignment-week to relative-window, and
  activity-category rule values/provenance;
- the support policy and whether out-of-support candidates are pruned or shown
  only as exploratory results;
- a defensible availability cutoff for previous marks. The official NN input
  requirement is currently unmet by strict inference; proxy mode is not
  leakage-cleared;
- what to return if Search exhausts states but some states cannot be scored by
  the NN, and how “best achievable marks” is selected for a course-level
  target;
- exact CSP variable/domain representation and whether AC-3 applies to the
  chosen constraint graph without additional modeling decisions;
- experiment instance selection, seed role, and runtime measurement protocol.

Do not select numeric click lengths, capacities, target marks, support
thresholds, heuristic parameters, or missing assignment data until the
documented-rule owner resolves them. The mapping is a declared simulation
input, not a discovered causal session-to-mark relationship.
